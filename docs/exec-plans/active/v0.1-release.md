# v0.1 公開

## 目的

PyPI に最初の版（0.1.0）を公開し、`pip install <名前>` で使えるようにする。

## 手順

- [x] パッケージ名を決める。**`unillm` は PyPI で使用済み**。区切り文字だけ違う `uni-llm` なども「似すぎ」として断られる見込みなので、import 名もそろえて変える（2026-11-14 に `switchllm` に決定）
- [ ] ライセンスを決めて `LICENSE` を置く
- [x] git 管理を始める（2026-11-09 に `git init` 済み）
- [x] 最初のコミットを作る（2026-11-14）。**作者名とメールアドレスをユーザーに確認してから**（GitHub の noreply アドレスを勧めている）。作業前（2026-11-09）の状態を index にステージしてあるので、先に `git commit` で「元の状態」をコミットし、そのあと `git add -A` で軽量化とドキュメント整備の作業をコミットする。**先に `git add` すると元の状態の記録が上書きされる**
- [x] 名前を `switchllm` に変える（2026-11-14）。**最初のコミットの後に、別のコミットで行う**。対象は `src/unillm/` のディレクトリ名と全 import、`pyproject.toml` の `name`、環境変数 `UNILLM_MODEL` → `SWITCHLLM_MODEL`、基底例外 `UniLLMError` → `SwitchLLMError`、Gemini の仮 ID の接頭辞 `unillm_`、README・CLAUDE.md・ARCHITECTURE.md・docs 全体。終わったら `git grep -i unillm` で、残りが履歴の記述（この計画の進捗ログなどと `completed/`）だけであることを確かめる
- [ ] GitHub にリポジトリを作る。名前は `switchllm`（README の `cd switchllm` と合わせる）
- [ ] [実 API 検証](real-api-verification.md) を終える
- [ ] `pyproject.toml` に公開用の情報を足す（`license` / `license-files` / `authors` / `keywords` / `classifiers` / `[project.urls]`）。`license = "MIT"` のような書き方には setuptools 77 以上が必要
- [ ] 空ファイル `py.typed` をパッケージに置き、wheel に含まれることを確かめる
- [ ] バージョン番号を1か所にまとめる（今は `pyproject.toml` と `__init__.py` の2か所）
- [ ] `CHANGELOG.md` を作る
- [ ] README のリンクを絶対 URL にする（PyPI のページでは相対リンクが切れる）。英語版の README を用意するか決める
- [ ] 脆弱性の報告窓口を決めて [SECURITY.md](../../SECURITY.md) に書く
- [ ] GitHub Actions で pytest を回す
- [ ] `python -m build` → `twine check dist/*` → 新しい venv で wheel を入れて import を確かめる
- [ ] TestPyPI に上げて、そこから入れられることを確かめる
- [ ] PyPI の Trusted Publishing を設定し、GitHub のリリースから公開する

## 判断ログ

- 2026-11-09: 機能を絞った軽量ライブラリとして出す。使い心地は下げない（[軽量化の記録](../completed/2026-11-09-lightweight-and-docs.md)）

- 2026-11-14: 基底例外の `UniLLMError` も `SwitchLLMError` に変え、旧名の別名は残さない。まだどこにも公開していないので、旧名で書かれた利用者のコードはない
