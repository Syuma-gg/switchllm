## 配布物を手元で確かめる

公開するときは `publish.yml` が同じ検査をする。`build` と `twine` はプロジェクトの依存に入れず、別の venv に入れて使う。

1. `python -m build --outdir <作業用フォルダ>/dist .`（sdist を作り、それを展開したものから wheel を作る）
2. `python -m twine check --strict <作業用フォルダ>/dist/*`
3. 新しい venv に wheel と pytest を入れ、sdist を展開した先で次の2つを通す
   - `python -m pytest`（sdist の `src/` を使う）
   - `python -m pytest -o "pythonpath=scripts e2e"`（インストールした wheel を使う）。`-o pythonpath=`（空）にすると、`tests/test_quality_gate.py` が `scripts/` を、`tests/test_recording.py` が `e2e/` を import できずに失敗する
4. リポジトリにできた `build/` を消す（`.gitignore` 済みだが、残す理由がない）

## 公開の設定

Trusted Publishing（OIDC）を使うので、API トークンを作って secret に入れる必要はない。PyPI と TestPyPI はアカウントが別。

| どこで | 何をする | 値 |
|---|---|---|
| PyPI（https://pypi.org/manage/account/publishing/） | pending publisher を足す | Project Name `switchllm` / Owner `Syuma-gg` / Repository name `switchllm` / Workflow name `publish.yml` / Environment name `pypi` |
| TestPyPI（https://test.pypi.org/manage/account/publishing/） | pending publisher を足す | 上と同じで、Environment name だけ `testpypi` |
| GitHub（Settings → Environments） | environment `pypi` を作る | Deployment branches and tags を Tag の `v*` に限る。Required reviewers に自分を入れる（PyPA のガイドが、PyPI に上げるたびに手で承認することを求めている） |
| GitHub（Settings → Environments） | environment `testpypi` を作る | 承認は要らない。限るなら Branch の `main` |

- secret と variable は要らない
- Required reviewers は、Private のリポジトリでは設定する欄が出なかった（2026-11-15）。Public にしてから設定した
- 開発者が1人なので、Prevent self-review は外している。入れると誰も承認できない

## 公開の順番

1. リポジトリを Public にする（済み）
2. Actions の「publish」を「Run workflow」で実行し、TestPyPI に上げる（済み）
   - 新しい venv で `pip install -i https://test.pypi.org/simple/ --extra-index-url https://pypi.org/simple/ switchllm` が入ることを確かめる（httpx は TestPyPI にないので、本家の PyPI から取る）
   - TestPyPI は同じ版を上げ直せない。やり直すときは版を変える
3. `CHANGELOG.md` の「0.1.0（未公開）」を公開日に書き換えてコミットし、push する
4. GitHub で Release を作る。タグは `v0.1.0`（`__version__` と違うと、ワークフローが止まる）。公開すると publish が走り、`pypi` の承認を待つので、承認する

## 判断ログ

- 2026-11-09: 機能を絞った軽量ライブラリとして出す。使い心地は下げない（[軽量化の記録](../completed/2026-11-09-lightweight-and-docs.md)）
- 2026-11-14: パッケージ名と import 名は `switchllm`
  - PyPI で、区切り文字の違う形も含めて空いていた。「文字列でプロバイダーを切り替える」という中心の機能をそのまま表す
  - `llmswitch` は、既存の `llm-switch` と似すぎていて断られる見込みのため外した
  - GitHub には、自動ルーティングのプロキシに同じ名前を使う小さなリポジトリがある。README の冒頭で「自動では切り替えない。文字列で選ぶ」とはっきり書く
- 2026-11-14: 基底例外も `SwitchLLMError` に変え、旧名の別名は残さない（まだ公開していなかったため）
- 2026-11-14: ライセンスは MIT。他人のアプリに組み込むライブラリなので、条件がゆるいほど使ってもらいやすい。唯一の依存の httpx（BSD）とも問題なく組み合わせられる
- 2026-11-14: 版の正本は `__init__.py` に置き、`pyproject.toml` がそれを読む。逆向き（`importlib.metadata.version()`）は、インストールせずに `src/` から動かしたときに失敗する
- 2026-11-14: CI は、Ubuntu では対応する Python の全版（3.10〜3.15）、Windows では最古版と最新版だけで回す
- 2026-11-14: 開発段階の classifier は `3 - Alpha`。[実 API 検証](real-api-verification.md) が終わったら `4 - Beta` にするか見直す
- 2026-11-14: `README.md` を英語にし、日本語版を `README.ja.md` に置く（作者の依頼）。設計文書と CHANGELOG は日本語のままにする
- 2026-11-14: sdist には、展開した先で全テストが通るだけのファイルを入れる（`MANIFEST.in`）。sdist からテストを走らせるパッケージ作成者がいるため。テストが読むファイルをルートに増やしたら、`MANIFEST.in` にも足す
