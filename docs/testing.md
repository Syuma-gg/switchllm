# テストの方針

switchllm はテスト駆動で開発する（2026-11-17 に作者が決めた）。振る舞いを変えるときは、先にその振る舞いを確かめるテストを書き、変更前のコードで失敗することを確かめてから直す。

品質検査（ruff・pytest・カバレッジ）の基準と、落ちたときの直し方は [品質検査の方針](quality-gates.md) にある。この文書は、どのテストをどの順で書くかを決める。

## テストの3つの層

| 層 | 置き場所 | ネットワーク | いつ回るか | 確かめること |
|---|---|---|---|---|
| モック | `tests/` | 使わない | 既定の `python -m pytest`、Stop フック、CI | リクエストの形、応答の読み方、境界値、例外、リトライ。`FakeAPI` に積んだ応答（各社の文書から作ったもの）を使う |
| 記録の再生 | `e2e/`（`--models` なし） | 使わない | 既定の `python -m pytest`、Stop フック、CI | 実 API で通ったやりとりを再生し、ライブラリが今も同じリクエストを送り、同じ応答を同じように読むこと |
| 実 API | `e2e/`（`--models` あり） | 使う（料金が発生する） | 手で回したときだけ | 各社が本当にその形式を受け付け、その形で返すこと（[E2E テスト](e2e-tests.md)） |

`tests/` で `FakeAPI`（fixture の `api`）を使うテストは、同期の `Client` と非同期の `AsyncClient` の2通りで回る（テスト名の `[sync]` / `[async]`）。非同期のときの `api.client()` は、`AsyncClient` を同期のテストから呼べるように包んだもの（`AsyncDriver`）を返すので、同じテストのまま両方を確かめられる（[判断](design-docs/async-client.md)）。非同期にしかないこと（並行の送信、待つ間にイベントループを止めないこと）は `tests/test_async_client.py` で確かめる。テストのための依存（pytest-asyncio など）は入れない

モックの層は、文書を読んで作った応答に頼っている。文書と実際の API が違っていても通ってしまう。記録の再生の層は、本物の応答を使うのでこの穴を埋める。さらに、実 API で確かめたリクエストからずれたら失敗するので、確かめた状態を守れる。

## 手順（テスト駆動）

1. **確かめたい振る舞いを、テストで書く。** API の形式なら、`tests/` で `FakeAPI` に応答を積み、送られたリクエスト本体を確かめる。境界値（0、空、上限、壊れた入力）も考える
2. **変更前のコードで、そのテストが失敗することを確かめる。** 失敗の理由が、確かめたいことと合っているかも見る（import の失敗などで落ちていないか）。通ってしまうなら、テストが振る舞いを確かめていない
3. **テストが通る、いちばん小さな変更をする**
4. **テストが通ったまま、整理する**
5. **品質検査を通す**（`python scripts/quality_gate.py --ci`。Claude Code では Stop フックが回す）
6. **報告では、変更前に失敗したことを伝える**

場面ごとの決まり:

- **不具合を直すとき**: 先に、不具合を再現するテストを書く。実 API で見つかった不具合は、その応答をモックのテストにも足す
- **API の仕様に関わる変更**: 先に一次情報で確かめる（[CLAUDE.md](../CLAUDE.md) の不変条件 7）。そのうえでテストを書き、実装する
- **記録の再生が失敗したとき**: ライブラリが、実 API で確かめたものと違うリクエストを送るようになっている。意図した変更なら、実 API で回し直して記録し直す（料金が発生するので、ユーザーの了承を得てから）。意図していないなら、変更のほうを直す。記録を手で書き換えて通さない
- **テストだけを足すとき**（今の振る舞いを固定する）: 手順 2 で失敗させるために、一時的にコードを壊して失敗することを確かめ、元に戻す（例: `if req.temperature is not None:` を `if req.temperature:` にする）

## 記録と再生

### 記録する

```powershell
python -m pytest e2e --models "anthropic:claude-sonnet-5-5,openai:gpt-5.5" --record
```

- 通ったテストだけを、`e2e/recordings/<テストのファイル>/<テストの名前>.json` に記録する。失敗したテストは記録しない（前の記録があれば残る）
- 記録に残すのは、リクエストの method・URL（`key` の引数を除く）・本体と、応答の status・`content-type`・`retry-after`・本文だけ。リクエストのヘッダー（APIキーが入る）と、ほかの応答のヘッダー（組織の ID など）は残さない
- 保存するときに、各プロバイダーのキーの環境変数の値を `<redacted>` に置き換える
- `tests/test_recording.py` が、記録にキーの形をした文字列やリクエストのヘッダーがないことを毎回確かめる
- 記録はリポジトリに入れる。コミットする前に差分を見て、意図しない内容がないかを確かめる

### 再生する

`--models` を渡さなければ、記録のあるテストだけを再生する（ネットワークを使わない）。既定の `python -m pytest` にも入る。

- 記録した応答を順に返し、ライブラリが送るリクエストが記録と同じかを確かめる。JSON として比べ、Gemini の仮 ID（`switchllm_` と12桁）だけは比べない（実行ごとに変わるため）
- 記録より多く呼んだとき、記録の一部を使わなかったときも失敗する
- 再生ではキーは要らない（偽のキーを使う）

## 実装

- 記録と再生: `e2e/e2e_recording.py`（テストは `tests/test_recording.py`）
- E2E の設定（実 API と再生の切り替え）: `e2e/conftest.py`。`AsyncClient` のテストは `open_async_client` で、接続をテストの中のイベントループで作って閉じる
- `tests/` のテストは `conftest` から import しない。共有するものは `tests/sample_tools.py` のような名前の違うモジュールに置く（`e2e/` にも `conftest.py` があり、両方を一度に回すと `import conftest` がどちらを指すか決まらない）
