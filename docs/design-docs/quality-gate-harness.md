# 品質検査をハーネスで回し、数字を通すために品質を落とさない

- 状態: 採用（2026-11-14）。他のプロジェクトでも使えるテンプレートにした（2026-11-15）
- 原則と仕組み、落ちたときの直し方: [品質検査の方針](../quality-gates.md)（テンプレートの文書）
- テンプレート: [harness/quality-gate/](../../harness/quality-gate/README.md)
- switchllm での設定: `pyproject.toml` の `[tool.ruff.lint]` と `[tool.coverage]`、CI は `.github/workflows/test.yml` の `quality` ジョブ

## 背景

AI にコードを書かせると、検査の数字（ruff の違反 0 件、カバレッジ）を満たす一番の近道を選びやすい。行を実行するだけで結果を確かめないテストを書く、`# noqa` や `# pragma: no cover` で黙らせる、基準の値を下げる、落ちるテストを消す、などである。

検査を確実に回すには、モデルの判断に任せる仕組み（skill や指示だけ）では足りない。一方で、仕組みだけでは「どう直すか」の判断は伝わらない。

## 決定

### 指示・Stop フック・CI の3層で回す（2026-11-14）

原則を CLAUDE.md と文書に書き、Stop フックで検査を回し、落ちたときに原則を Claude に返す。検査を緩める変更は機械で見つけて見直させ、CI を最後の砦にする。原則と仕組みの詳細は [品質検査の方針](../quality-gates.md) にある。

導入時のカバレッジは 87.68% だったので、`fail_under` は 87 から始めた（ラチェット）。

### 他のプロジェクトでも使えるテンプレートにする（2026-11-15）

検査の仕組みを、Python のプロジェクトならどこでも使えるテンプレートにした（[harness/quality-gate/](../../harness/quality-gate/README.md)）。

- **スクリプトは全プロジェクトで同じファイルにする。** プロジェクトごとの違いは `pyproject.toml`（ruff・pytest・coverage の設定と `[tool.quality-gate]`）に書く。テンプレートの検査を直したら、ファイルを上書きコピーするだけで各プロジェクトに配れる
- **どのファイルを検査するかは、各ツールの設定に任せる。** ruff はプロジェクト全体から設定の除外を除いたもの、テスト関数の数は pytest の `testpaths` の中で数える。検査の範囲を決める設定を別に持つと、そこを狭めることが新しい抜け道になる。各ツールの設定なら、すでに緩みを見張っている
- **switchllm を最初の利用者にする。** テンプレートの `files/` と同じものを switchllm に置き、`tests/test_harness.py` が一致を確かめる。switchllm で検査が回り続けることが、テンプレートが使えることの確認になる
- **置き場所は、いったん switchllm の中にする。** 作者のハーネスをまとめるフォルダーが決まったら移す（[負債](../exec-plans/tech-debt-tracker.md)）

## 却下した案

- **skill で検査させる**: skill は呼ばれたときに読む手順書で、いつ呼ぶかはモデルが判断する。急いでいるときに飛ばされる
- **全体のカバレッジ 100% を合格ラインにする**: 導入時は 87%。いきなり合格ラインにすると、原則を破る圧力がかかる。ラチェットで少しずつ上げる
- **検査を緩める変更を CI で失敗にする**: ユーザーが了承した正当な変更まで止まる。了承は会話で取り、CI では止めない
- **LLM に差分を判定させるフック（prompt 型・agent 型）**: Stop では使えない（ツールのイベント専用）。編集のたびに回すと遅く、費用もかかる
- **テンプレートを Claude Code のプラグインや pip パッケージにする**: 作者の希望で、コピーして使うテンプレートにした。配り直しはファイルの上書きで足りる
- **検査するフォルダーをスクリプトの定数で持つ（導入時の形）**: プロジェクトごとにスクリプトを書き換えることになり、テンプレートの更新を上書きで配れない

## 影響

- 開発用の依存に ruff と coverage を足した（ランタイム依存は httpx のまま）
- ruff はプロジェクト全体（`examples/`・`harness/` を含む）を検査する
- `fail_under` を上げたら、[QUALITY_SCORE.md](../QUALITY_SCORE.md) のカバレッジの記録も直す
- 検査のスクリプト・テスト・方針の文書を直すときは、テンプレートの `files/` も同じ変更で直す（`tests/test_harness.py` が照合する）
- フックは Git Bash（Windows）か bash で動く。仮想環境（`.venv` か `venv`）がないとフックはエラーを出して止めない
